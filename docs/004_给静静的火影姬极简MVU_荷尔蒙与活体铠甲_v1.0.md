# 《火影姬世界》极简 MVU 施工单 v1.1

> 交接对象：静静 / MVU施工阶段
> 唯一静态世界书基线：`dist/火影姬世界_worldbook-ready_v1.0.json`
> 原则：世界书正文已封版，MVU只做业务显示与记录，不重做设定、时间线、角色、地点，也不复制咩咩预设已有状态。

---

## 1. MVU职责只保留两件事

1. 记录并显示**已经遇见的角色**当前荷尔蒙值。
2. 记录并显示这些角色**当前装备的活体铠甲**。

明确禁止再加入：

- 当前时间 / 日期
- 当前地点
- 忍阶 / Level / EXP
- 好感度 / 信任度 / 关系
- HP / 查克拉条
- 任务列表
- 背包
- 地图
- 角色资料副本
- 忍术列表副本
- 发情期阶段副本
- 活体铠甲同步等级副本
- 战力值
- 时间线全文或事件导演状态

这些要么由咩咩预设维护，要么已经属于世界书事实，不得在MVU复制第二份。

---

## 2. 唯一业务 Schema

MVU只允许两个长期 Record：

```js
export const Schema = z.object({
  角色荷尔蒙: z.record(
    z.string(),
    z.number().int().min(0).max(100)
  ).prefault({}),

  角色活体铠甲: z.record(
    z.string(),
    z.string()
  ).prefault({}),
}).prefault({
  角色荷尔蒙: {},
  角色活体铠甲: {},
});
```

不建立第三个“已遇见角色”数组。

**键存在即代表该角色已经遇见。**

角色第一次真实进入当前剧情后才建档；未遇见角色不得预建，不得一次性把92条角色塞进MVU。

---

## 3. 荷尔蒙值规则

世界书唯一事实源：

`worldbook/settings/04_荷尔蒙查克拉运行细则_v0.4.md`

其中 `核心设定:荷尔蒙值与单回合跃迁` 负责数值含义。

MVU只记录数值，不重新解释世界观。

### 3.1 范围

```text
0 ~ 100
```

强制：

```text
最终值 = clamp(原值 + 本回合变动, 0, 100)
```

### 3.2 推荐变动手感

参考咩咩预设好感度的小步更新逻辑：

- +1：轻微情绪 / 环境 / 训练 / 身体刺激
- +3：明确持续的高活性刺激、激烈训练、战斗压力或铠甲反馈
- +5：强烈共振、突破边缘、剧烈情绪冲击或高强度铠甲刺激
- +6~+10：仅用于正文明确发生的爆发性荷尔蒙跃迁
- -1 / -3 / -5：休息、恢复、医疗、降档、解除高强度刺激等

没有足够事实支持变化时保持原值；禁止为了让UI“有变化”而每回合强制加点。

---

## 4. 活体铠甲记录规则

`角色活体铠甲` 只保存当前装备名。

只有正文明确发生以下事件时才修改：

- 装备
- 解除
- 更换
- 铠甲被破坏到无法继续装备

不得因为角色“拥有某套铠甲”就自动写成已装备。

不得额外保存同步等级、负荷、耐久、形态阶段或部位覆盖率；这些仍由正文与世界书负责。

---

## 5. 唯一上游事实块：`<hormone>`

本卡直接参考《因果法典》最终采用的**结构标签驱动**思路，不采用后来已经回退的复杂刷新补丁。

每条 AI 正文末尾必须输出且只输出一个完整的：

```text
<hormone>
漩涡鸣子|37|九尾九喇嘛活体铠甲
日向雏田|12|无
我爱罗奈|64|一尾守鹤活体铠甲
</hormone>
```

字段顺序固定：

```text
角色正式名 | 当前荷尔蒙值 | 当前装备活体铠甲
```

### 5.1 快照原则

`<hormone>` 是**当前已遇见角色的完整快照**，不是只写“本回合变化的人”。

已经建档但本回合没变化的角色仍保留上一值；未遇见角色不输出。

这保证任意一条最新 AI 楼都能独立恢复当前两张 Record，不依赖扫描旧楼，也不依赖前端补算。

### 5.2 唯一性

每条 AI 回复：

- 必须有一个 `<hormone>...</hormone>`
- 不得缺失
- 不得重复输出两个
- 不得输出半截未闭合标签

如果下一楼没有 `<hormone>`，判定为**模型输出契约失败**，不是“MVU刷新失败”。

禁止用轮询、延迟二刷、DOM扫描补丁等方式掩盖上游没有输出事实块的问题。

---

## 6. 咩咩 MVU 写入方式

咩咩原生变量更新仍然负责最终写入两个 Record。

`<hormone>` 只是可验证的结构化事实块 / 展示源；变量更新规则必须让：

```text
角色荷尔蒙[角色名] = <hormone>中的数值
角色活体铠甲[角色名] = <hormone>中的铠甲名
```

同一角色不得因为重复解析同一楼而二次加值；`<hormone>` 写的是**最终值快照**，不是 `+3` 这样的增量指令。

因此：

```text
旧值 20
本回合 +3
<hormone> 中直接输出 23
```

而不是：

```text
<hormone>漩涡鸣子|+3|...</hormone>
```

这样不会出现重复应用变动的问题。

## 7. 正则美化：直接复用《因果法典》的最终思路

不要把 `<hormone>` 原始文本直接裸露给玩家。

必须制作一条专用正则，负责：

1. 匹配完整 `<hormone>[\s\S]*?</hormone>`；
2. 将结构块替换/美化为火影姬风格的小面板；
3. 保留块内数据供 MVU / 调试识别所需的稳定结构；
4. 不依赖 `role==='assistant'`、消息事件监听、120ms 二刷或1秒轮询。

### 7.1 推荐匹配

```regex
/<hormone>[\s\S]*?<\/hormone>/g
```

若 SillyTavern 正则环境使用字符串形式，则按实际 JSON 转义，不允许把 `\s` / `\S` 二次错误转义成普通文本。

### 7.2 美化目标

原始：

```text
<hormone>
漩涡鸣子|37|九尾九喇嘛活体铠甲
日向雏田|12|无
</hormone>
```

视觉上显示为简洁小卡：

```text
火影姬 · 荷尔蒙记录
漩涡鸣子  37 / 100  ████░░  九尾九喇嘛活体铠甲
日向雏田  12 / 100  █░░░░░  无
```

只显示：

- 角色名
- 荷尔蒙数值
- 简单进度条
- 当前活体铠甲

角色多时纵向滚动；不做分页状态机。

---

## 8. 只显示已遇见角色

UI / 正则美化结果只读取 `<hormone>` 当前快照里的角色。

未遇见角色：

- 不输出
- 不显示
- 不预建档
- 不显示0/100占位

已经遇见但暂时不在场的角色仍保留最后记录值，因此继续存在于完整快照中。

## 9. 与咩咩预设的关系

咩咩预设原生维护：

- 好感度
- 信任度
- 关系
- 时间 / 日期
- 玩家基础状态
- 世界时间线运行

全部继续使用，不复制到MVU。

本卡只新增：

```text
角色荷尔蒙
角色活体铠甲
```

两者与好感度、信任度、关系相互独立；高好感不自动提高荷尔蒙，高荷尔蒙也不自动等于恋爱、信任或关系升级。

## 10. 世界书新增规则接线

世界书现有：

`核心设定:荷尔蒙值与单回合跃迁`

其负责：

- 荷尔蒙值范围 0~100
- 小步更新
- 单次 +6~+10 只用于明确爆发性跃迁
- 单次增加 >5 时产生高活性溢出反馈

该反馈不额外存第三个 MVU flag；是否发生由本回合数值变化直接判定。
