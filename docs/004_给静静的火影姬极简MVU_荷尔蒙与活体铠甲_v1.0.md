# 《火影姬世界》极简 MVU 施工单 v1.2

> 交接对象：静静 / MVU施工阶段
> 唯一静态世界书基线：`dist/火影姬世界_worldbook-ready_v1.0.json`
> 参考机制：`无职转生_沙盒_因果法典_worldbook-ready_v1.4-order-final.json` + `无职转生_沙盒_因果法典_实机测试_v1.4.json`
> 原则：世界书正文已封版；MVU只做荷尔蒙记录与活体铠甲记录，不重做人物、地点、时间线，也不复制咩咩预设已有状态。

---

## 1. MVU职责只保留两件事

1. 记录并显示已经遇见的角色当前荷尔蒙值。
2. 记录并显示这些角色当前装备的活体铠甲。

明确禁止新增：时间、地点、忍阶、Level、EXP、好感度、信任度、关系、HP、查克拉条、任务、背包、地图、忍术列表、发情期阶段、铠甲同步等级、铠甲负荷、战力值、剧情导演状态。

这些要么由咩咩预设维护，要么已经属于世界书事实，不得复制第二份。

---

## 2. 唯一业务 Schema

只允许两个长期 Record：

```js
export const Schema = z.object({
  角色荷尔蒙: z.record(
    z.string(),
    z.number().int().min(0).max(100)
  ).prefault({}),

  角色活体铠甲: z.record(
    z.string(),
    z.string()
  ).prefault({}),
}).prefault({
  角色荷尔蒙: {},
  角色活体铠甲: {},
});
```

不建立第三个“已遇见角色”数组。

**键存在即代表该角色已经遇见。**

角色第一次真实进入当前剧情后才建档；未遇见角色不得预建，不得一次性初始化全部人物。

## 3. 荷尔蒙值与铠甲更新

世界书事实源：

`worldbook/settings/04_荷尔蒙查克拉运行细则_v0.4.md`

荷尔蒙值范围：`0~100`。

最终值始终执行：

```text
clamp(原值 + 本回合变动, 0, 100)
```

推荐小步变动：

- `+1`：轻微情绪 / 环境 / 训练 / 身体刺激
- `+3`：明确持续的高活性刺激、激烈训练、战斗压力或铠甲反馈
- `+5`：强烈共振、突破边缘、剧烈情绪冲击或高强度铠甲刺激
- `+6~+10`：仅用于正文明确发生的爆发性荷尔蒙跃迁
- `-1 / -3 / -5`：休息、恢复、医疗、降档、解除高强度刺激等

没有事实支持变化时保持原值；禁止为了让UI动起来而强行加点。

`角色活体铠甲` 只保存当前装备名；只有正文明确发生装备、解除、更换或失效时才改。不得因为角色“拥有”某套铠甲就自动视作已经装备。

## 4. v1.4经验：正文输出稳定性必须由上游双保险负责

本卡**禁止复用旧 v1.3 的 `affinity_format` 劫持方案**。

《因果法典》v1.4 已经改为：

1. 世界书常驻核心规则强制每回合输出；
2. `post_history_instructions` 再提供一段短保险；
3. MVU只读取事实块，不负责“制造”事实块；
4. 正则只负责显示，不承担业务真值。

火影姬完全照此思路施工。

## 5. 唯一事实块：`<hormone>`

每一次正常 assistant 回复都必须在所有其他正文与结构化块完成后、消息结束前，额外输出且只输出一个完整：

```text
<hormone>
漩涡鸣子|37|九尾九喇嘛活体铠甲
日向雏田|12|无
我爱罗奈|64|一尾守鹤活体铠甲
</hormone>
```

字段顺序永久锁死：

```text
角色正式名 | 当前荷尔蒙最终值 | 当前装备活体铠甲
```

### 5.1 完整快照

`<hormone>` 必须是**当前全部已遇见角色的完整快照**，不是只列本回合变化人物。

已经建档但本回合没有变化的角色继续输出上一值；未遇见角色不输出。

数值写最终值，不写增量：

```text
旧值20，本回合+3 → 输出23
```

禁止写：

```text
漩涡鸣子|+3|...
```

### 5.2 每回合硬规则

- 必须存在一个且只有一个 `<hormone>...</hormone>`。
- 即使所有人物本回合荷尔蒙均未变化，也必须输出完整块。
- 即使没有任何人装备活体铠甲，也必须输出完整块，铠甲字段写 `无`。
- 不得输出两个块。
- 不得输出半截、未闭合块。
- 不得把本块包进 `<status>`、`<affinity>`、`<UpdateVariable>`、记忆块或其他标签内部。
- 推荐位置：回复最后一个结构化块。

如果正文缺少 `<hormone>`，判定为**上游输出契约失败**，不是“MVU刷新失败”。

禁止恢复已经验证无意义的轮询、120ms二刷、DOM扫描等补丁去掩盖上游漏输出。

## 6. 必须新增的世界书输出保险

最终装配必须新增一条**蓝灯 / constant=true**核心规则：

```text
核心规则:火影姬·每回合荷尔蒙记录与输出
```

其正文必须明确：

- 本规则是 `<hormone>` 的唯一实时输出协议；
- 不依赖 `status_format / affinity_format / special_status_format / npc_log` 等预设变量槽；
- 每次正常 assistant 回复结束前必须且只能输出一个完整 `<hormone>`；
- 先继承上一回合全部已遇见角色，再处理本回合变化；
- 新遇见角色才新增键；未遇见角色绝不预建；
- 本回合没有变化的旧角色仍保留原值；
- 荷尔蒙最终值锁在0~100；
- 活体铠甲只按正文明确装备事实更新；
- 不在正文重复解释计算过程。

该条属于MVU接线所需的技术输出规则，不得借此修改其他世界书正文。

最终派生卡的 `post_history_instructions` 必须追加以下含义，保持极短，不复制整套算法：

```text
【火影姬荷尔蒙输出保险】
每次正常assistant回复结束前，必须额外输出且只输出一个完整<hormone>...</hormone>。
此要求独立于status/affinity/特殊状态/记忆等预设变量槽，即使本回合所有数值均为0变化也不得省略。
具体继承、变化与铠甲更新规则严格服从世界书《核心规则:火影姬·每回合荷尔蒙记录与输出》。
禁止输出第二个hormone块。
```

如果原卡已有 `post_history_instructions`，只能**追加**这段，不覆盖原内容。

## 8. 咩咩变量层

咩咩原生 `<UpdateVariable>` 协议继续使用，不造第二套协议。

两个 Record 的最终结果必须与当轮 `<hormone>` 快照一致：

```text
角色荷尔蒙[角色名] = 当前快照中的数值
角色活体铠甲[角色名] = 当前快照中的铠甲名
```

`<hormone>` 是公开结构化事实源；MVU不得从普通叙述自行重算另一套数值。

---

## 9. 正则：只做美化，不做业务

参考《因果法典》v1.1兼容美化正则的成熟做法，使用宽匹配：

```regex
/<hormone>\s*([\s\S]*?)\s*<\/hormone>\s*/gi
```

禁止写一条把角色行数、人物名或字段数量全部硬编码死的超长正则。

正则职责：

- 把原始 `<hormone>` 包成紧凑的“本回合荷尔蒙记录”视觉块；
- 允许将 `$1` 原样放进折叠内容用于调试；
- 不修改 Record；
- 不计算增量；
- 不负责找最新楼；
- 不负责轮询刷新。

详细美术必须服从独立视觉规范，不得由静静自行设计第二套风格。

## 10. MVU主面板

主面板只显示两个字段：

- 角色名 + 当前荷尔蒙 `N / 100` + 一条进度条；
- 当前活体铠甲名称。

角色多时只纵向滚动，不分页、不做地图、不做第二层资料页。

MVU主面板只保留一个实例；不得在每条历史AI楼复制完整主面板。
