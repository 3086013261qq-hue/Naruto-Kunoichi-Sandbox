# 《火影姬世界》极简 MVU 施工单 v1.0

> 交接对象：静静 / MVU施工阶段
> 唯一静态世界书基线：`dist/火影姬世界_worldbook-ready_v1.0.json`
> 原则：世界书正文已封版，MVU只做业务显示与记录，不重做设定、时间线、角色、地点，也不复制咩咩预设已有状态。

---

## 1. MVU职责只保留两件事

1. 记录并显示**已经遇见的角色**当前荷尔蒙值。
2. 记录并显示这些角色**当前装备的活体铠甲**。

明确禁止再加入：

- 当前时间 / 日期
- 当前地点
- 忍阶 / Level / EXP
- 好感度 / 信任度 / 关系
- HP / 查克拉条
- 任务列表
- 背包
- 地图
- 角色资料副本
- 忍术列表副本
- 发情期阶段副本
- 活体铠甲同步等级副本
- 战力值
- 时间线全文或事件导演状态

这些要么由咩咩预设维护，要么已经属于世界书事实，不得在MVU复制第二份。

---

## 2. 唯一业务 Schema

MVU只允许两个长期 Record：

```js
export const Schema = z.object({
  角色荷尔蒙: z.record(
    z.string(),
    z.number().int().min(0).max(100)
  ).prefault({}),

  角色活体铠甲: z.record(
    z.string(),
    z.string()
  ).prefault({}),
}).prefault({
  角色荷尔蒙: {},
  角色活体铠甲: {},
});
```

不建立第三个“已遇见角色”数组。

**键存在即代表该角色已经遇见。**

角色第一次真实进入当前剧情后：

```yaml
角色荷尔蒙:
  漩涡鸣子: 0
角色活体铠甲:
  漩涡鸣子: 无
```

未遇见角色不得预建档，不得一次性把92条角色塞进MVU。

## 3. 荷尔蒙值规则

世界书唯一事实源：

`worldbook/settings/04_荷尔蒙查克拉运行细则_v0.4.md`

其中 `核心设定:荷尔蒙值与单回合跃迁` 负责数值含义。

MVU只记录数值，不重新解释世界观。

### 3.1 范围

```text
0 ~ 100
```

强制：

```text
最终值 = clamp(原值 + 本回合变动, 0, 100)
```

### 3.2 推荐变动手感

参考咩咩预设好感度的“小步更新”思路：

- +1：轻微情绪 / 环境 / 训练 / 身体刺激
- +3：明确持续的高活性刺激、激烈训练、战斗压力或铠甲反馈
- +5：强烈共振、突破边缘、剧烈情绪冲击或高强度铠甲刺激
- +6~+10：仅用于正文明确发生的爆发性荷尔蒙跃迁
- -1 / -3 / -5：休息、恢复、医疗、降档、解除高强度刺激等

禁止为了让UI“有变化”而每回合强制加点。

没有足够事实支持变化时：**保持原值。**

## 4. 活体铠甲记录规则

`角色活体铠甲` 只保存当前装备名。

示例：

```yaml
角色活体铠甲:
  漩涡鸣子: 九尾九喇嘛活体铠甲
  日向雏田: 无
  我爱罗奈: 一尾守鹤活体铠甲
```

只有正文明确发生以下事件时才修改：

- 装备
- 解除
- 更换
- 铠甲被破坏到无法继续装备

不得因为角色“拥有某套铠甲”就自动写成已装备。

不得额外保存：

- 同步等级
- 负荷
- 铠甲耐久
- 形态阶段
- 部位覆盖率

这些都由正文与世界书负责。

---

## 5. 只显示已遇见角色

UI从 `角色荷尔蒙` 的键集合取角色。

若某角色不存在于该Record：

- 不显示
- 不预建档
- 不显示 `0/100` 占位

角色首次登场后才加入。

若某角色已建档但当前不在场，仍保留其最后记录值，可继续在“已遇见角色”列表中查看。

## 6. UI：单一小面板

不做多页复杂MVU。

建议标题：

```text
火影姬 · 荷尔蒙记录
```

每个角色一行：

```text
漩涡鸣子   37 / 100   ███████░░░   九尾九喇嘛活体铠甲
日向雏田   12 / 100   ██░░░░░░░░   无
我爱罗奈   64 / 100   ████████████   一尾守鹤活体铠甲
```

UI重点：

- 数字
- 一条简洁进度条
- 活体铠甲名称

除此之外不加角色头像、好感、关系、忍阶、地点、任务等信息。

角色很多时允许纵向滚动；不要做分页状态机。

## 7. 刷新机制：复用《因果法典》已经验证过的稳定方案

必须避免“首楼正常、后续楼层长期停在旧值”的旧bug。

### 7.1 assistant兼容识别

不得写死：

```js
role === 'assistant'
```

兼容条件：

```js
message?.is_user !== true && (!message?.role || message?.role === 'assistant')
```

正文兼容：

```js
message?.message ?? message?.mes ?? ''
```

### 7.2 三层刷新

每次酒馆消息事件：

```text
立即 refresh()
→ setTimeout(refresh, 120)
→ 每1秒轮询兜底
```

UI只允许一个实例。

host始终迁移到最新 assistant 楼层，不允许每楼复制一整套面板。

流式输出期间如果MVU状态尚未完成写入：

- 保留上一次有效显示
- 不清空成0
- 等本轮变量写入完成后自动切换最新值

### 7.3 去重

同一个 message id 被轮询多次时：

- 只刷新显示
- 不重复应用数值变动
- 不重复建档

变量变动本身由咩咩 MVU 原生更新规则负责，UI只读当前状态。

## 8. 与咩咩预设的关系

咩咩预设原生：

- 好感度
- 信任度
- 关系
- 时间 / 日期
- 玩家基础状态
- 世界时间线运行

全部继续使用，不复制到MVU。

本MVU的：

```text
角色荷尔蒙
角色活体铠甲
```

与好感度、信任度、关系相互独立。

高好感不自动提高荷尔蒙；高荷尔蒙也不自动等于恋爱、信任或关系升级。

## 9. 世界书新增规则接线

当前新增：

`核心设定:荷尔蒙值与单回合跃迁`

其中：

- 荷尔蒙值范围 0~100
- 小步更新
- 单次 +6~+10 只用于明确爆发性跃迁
- 单次增加 >5 时产生高活性溢出反馈

对明确成年角色，该阈值允许触发泌乳反射与乳汁喷溢；未成年角色不使用乳腺/性化反馈，只使用非性化高活性过载表现。

这属于世界书规则，不额外存第三个 MVU flag；是否发生反馈由“本回合变动值 > 5”直接判定。
