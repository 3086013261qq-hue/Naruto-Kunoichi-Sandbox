## 二、业务只允许两件事

独立 MVU 只记录并显示：

1. 已遇见角色当前荷尔蒙值：`0~100`。
2. 已遇见角色当前装备的活体铠甲名称；无则为 `无`。

长期业务 Schema 只允许：

```js
z.object({
  角色荷尔蒙: z.record(z.string(), z.number().int().min(0).max(100)).prefault({}),
  角色活体铠甲: z.record(z.string(), z.string()).prefault({}),
})
```

禁止增加第三个长期业务字段。

不建立“已遇见角色”数组：Record 键存在即表示已经遇见。

## 三、`<hormone>` 输出方式：严格参考无职 v1.4 最终方案

禁止复用无职旧 v1.3 的 `affinity_format` 槽方案。
禁止恢复 120ms 二刷、1秒轮询等旧补丁。

静静只准备两个待组装 fragment：

### A. 常驻蓝灯核心规则 fragment

每次正常 assistant 回复必须在所有正文与其他结构块之后、消息结束前，额外输出且只输出一个完整：

```text
<hormone>
角色正式名|当前荷尔蒙值|当前活体铠甲
角色正式名|当前荷尔蒙值|无
</hormone>
```

硬规则：

- 即使本回合全部无变化，也必须输出完整块。
- 未遇见角色不得输出。
- 已遇见但本回合不在场者继续保留上一值，形成完整快照。
- 数值写最终值，不写 `+3` 之类增量。
- 一个回复不得输出第二个 `<hormone>`。
- 不得嵌套进 `<status>`、`<affinity>`、`<wlog>` 等其他结构块。

### B. post-history 短保险 fragment

只重复：

- 每次正常 assistant 回复结束前必须有一个完整 `<hormone>...</hormone>`；
- 数值与铠甲更新服从正式规则；
- 禁止第二个 hormone 块。

这两个 fragment 只能输出到模块 integration 目录，**禁止静静写入卡体或世界书。**

## 四、正则美化

只使用宽匹配：

```regex
/<hormone>\s*([\s\S]*?)\s*<\/hormone>\s*/gi
```

禁止逐字段超长脆弱正则。

正文显示为一个小折叠条：

```text
♡ 荷尔蒙记录 · 本回合
```

展开后显示 `$1` 快照，便于实机排查。

正则只负责视觉包装，不计算状态、不加载主背景、不复制完整 MVU。

## 六、锁屏画廊加载规则

锁屏只使用静态 CDN 图片。

加载原则：

- 初始只加载当前页。
- 允许预加载相邻 `±1` 页。
- 禁止一次预加载整本 28/33 页。
- 翻到下一本时才请求下一本页面。
- 图片加载失败显示纯 CSS 占位，不阻断进入主 MVU。

交互：

- 左右滑：上一页 / 下一页。
- 中央轻触：进入主 MVU。
- 滑动与点击必须区分，禁止滑页误触进入。
- 记住上次页码。
- 两卷首尾自然衔接；卷一最后一页继续右滑进入卷二第一页。
- 禁止自动轮播。
- 禁止 3D 翻书、卷页、粒子、闪屏。

锁屏画廊是唯一允许横向滑动的区域；主 MVU 禁止横向分页。

## 八、数据与 UI 关系

`<hormone>` 是每回合可验证的完整快照。

独立 MVU 可以把最新有效快照机械同步进两个 Record，但不得自行推断荷尔蒙变化，不得自行判断铠甲是否装备。

若某回合缺失 `<hormone>`：

- 保留上一条有效快照用于显示；
- QA 标记“本回合 hormone 输出缺失”；
- 不清零；
- 不自行补算；
- 根因仍判为上游输出契约失败。
