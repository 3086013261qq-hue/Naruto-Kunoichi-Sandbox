## 二、业务只有两件事

独立 MVU 只记录并显示：

1. 已遇见角色当前荷尔蒙值，范围 0~100。
2. 已遇见角色当前装备的活体铠甲名称；无则为 `无`。

长期业务 Schema 只允许：

```js
z.object({
  角色荷尔蒙: z.record(z.string(), z.number().int().min(0).max(100)).prefault({}),
  角色活体铠甲: z.record(z.string(), z.string()).prefault({}),
})
```

禁止增加第三个长期业务字段。

不建立“已遇见角色”数组：Record 键存在即表示已经遇见。

## 三、`<hormone>` 输出方式：严格对齐无职 v1.4 成熟方案

不要复用旧 v1.3 的 `affinity_format` 槽方案。
不要用轮询、120ms 二刷、1秒刷新补丁掩盖上游漏输出。

独立模块只准备两个待组装片段：

### 1. 常驻蓝灯核心规则片段

要求每次正常 assistant 回复在所有其他正文/结构块结束后、消息结束前，额外输出且只输出一个完整：

```text
<hormone>
角色正式名|当前荷尔蒙值|当前活体铠甲
角色正式名|当前荷尔蒙值|无
</hormone>
```

硬规则：

- 即使本回合全部数值无变化，也必须输出完整块。
- 未遇见角色不得输出。
- 已遇见但本回合不在场的角色继续保留上一值，形成完整快照。
- 数值写最终值，不写 `+3` 等增量。
- 一个回复不得输出第二个 `<hormone>`。
- 不得把本块包进 `<status>`、`<affinity>`、`<wlog>` 或其他结构块内部。
- 推荐作为回复最后一个结构化块。

### 2. post-history 短保险片段

只重复三件事：

- 每次正常 assistant 回复结束前必须有一个完整 `<hormone>...</hormone>`；
- 具体数值与铠甲更新服从本卡正式荷尔蒙/活体铠甲规则；
- 禁止第二个 hormone 块。

静静只能生成以上两个 fragment 文件，禁止把它们写进现有卡体。

## 六、ZIP 锁屏画廊实现锁死

使用成熟浏览器端 ZIP 读取方式，例如 JSZip 3.10.1；允许从稳定 CDN 加载库，但不得把 ZIP Base64 内嵌进角色卡。

加载原则：

- 初次进入只 fetch 当前卷 ZIP；另一卷直到用户翻到该卷才加载。
- ZIP 内只接受 `png/jpg/jpeg/webp/gif` 图片条目。
- 排除 `__MACOSX/`、目录项和隐藏文件。
- 图片条目按自然路径顺序排序。
- 只对当前页与相邻 ±1 页生成 Blob URL。
- 离开远页后 `URL.revokeObjectURL()`，禁止一次性把整卷全部解码成 DOM 图片。
- 切换下一卷后上一卷可保留 ArrayBuffer/ZIP 对象缓存；若 Android 内存压力实测明显，则允许释放上一卷缓存，但不得改成全量预解码。
- 加载失败显示纯 CSS 占位，不影响进入主 MVU。

交互：

- 左右滑：上一页 / 下一页。
- 中央轻触：进入主 MVU。
- 滑动阈值与点击必须区分，禁止滑页时误触进入。
- 记住上次页码。
- 禁止自动轮播。
- 禁止 3D 翻书、页面卷曲、粒子、闪屏。

锁屏画廊是唯一允许横向滑动的区域；主 MVU 不允许横向分页。

## 八、数据与 UI 关系

`<hormone>` 是每回合可验证的完整快照。

独立 MVU 模块可以把最新有效快照机械同步进两个 Record，但不得自行推断荷尔蒙变化、不得自行判断铠甲是否装备。

如果某一回合缺失 `<hormone>`：

- 保留上一条有效快照用于显示；
- 明确标记“本回合 hormone 输出缺失”用于 QA；
- 不清零、不自行补算；
- 根因仍判为上游输出契约失败。

不得恢复旧版“120ms 二刷 / 1秒轮询 / role==='assistant'”方案。
