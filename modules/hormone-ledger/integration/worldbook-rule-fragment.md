# 待组装：荷尔蒙完整快照输出规则

建议配置：enabled=true；constant=true（常驻蓝灯）；无关键词；正式组装时按现有输出规则段位确定 position/order。本文件不是已安装的世界书条目。

每个正常 assistant 回复，必须在所有正文与其他结构块之后、消息结束前，输出且只输出一个完整的 `<hormone>...</hormone>`。无变化也不得漏块，不得重复输出。

固定格式：

```text
<hormone>
角色正式名|当前最终荷尔蒙值|当前活体铠甲
</hormone>
```

- 一行一个已经遇见的角色。未遇见的角色不得提前建档、不得输出。
- Record 中存在角色名键即表示已经遇见；初始两 Record 均为空。
- 数值为 0～100 的整数最终值，不写 +3/-1 等增量，不写百分号。
- 活体铠甲必须写当前真实装备名称；无铠甲统一写“无”。具体更新服从正式世界规则，本片段不另造增减公式或装备判断。
- 每回合继承上一条有效快照中的全部已遇见角色；未在场者仍保留上一回合的数值与铠甲。本回合发生正式变更者填写变更后的最终值。
- 按首次遇见顺序输出，不按数值排序。未遇见任何角色时仍输出一个完整空块。
- hormone 必须是顶层结构，禁止包进 status、affinity、wlog 或其他 XML 中；禁止在同一回复输出第二个 hormone，包括示例、分析、附录中的第二块。
- 原始 hormone 是本模块唯一运行时事实源。不得另行输出用于更新这两个 Record 的 JSONPatch 或另一套结构；不得让独立更新模型根据正文再次推算。
- 若上一回合漏块，本回合继续从最后一条有效快照继承。漏块属于上游输出契约失败，不能靠刷新或推断替代本回合完整输出。

长期业务数据只有：`角色荷尔蒙: Record<string, int[0,100]>`、`角色活体铠甲: Record<string,string>`。不得新增阶段、同步率、耐久、关系或其他长期字段。
